01 / The Goal

Replace separate tools with one connected work experience

PrimeView Nexus is intended to bring time tracking, internal communication, and task workflows together without forcing employees to manage separate application identities or disconnected workspaces.

01

Fragmented employee workflows

Time tracking, chat, and task activity were separate concerns. Nexus provides one desktop entry point for all three.

02

Duplicate authentication risk

A separate desktop username/password flow would create additional credential handling and session-management complexity.

03

Realtime and API requirements

Chat and task-related interactions require a backend model that supports application APIs, sessions, and realtime updates.

04 / Authentication

Hub-first authorization for the desktop application

The desktop app does not need its own username/password form. The employee authenticates through PrimeView Hub and a short-lived authorization flow signs the desktop application in.

6. LogoutLogout clears/revokes the desktop session and requires Hub authorization again.

06 / Engineering Challenges

Designing one product across multiple system boundaries

The key challenge is not simply combining three screens; it is coordinating identity, desktop state, backend services, realtime behavior, and deployment without tightly coupling every feature.

Challenge

Single employee identity across web and desktop

A separate desktop credential store would duplicate authentication and complicate access control.

Approach

Use PrimeView Hub as the employee authentication entry point and authorize the desktop application through a one-time session/device flow.

Challenge

Different workspace behaviors

Time tracking, chat, and tasks have different state models and update patterns.

Approach

Keep each workspace logically separated inside a shared desktop shell and communicate through defined service contracts.

Challenge

Realtime communication without server-bound application logic

Chat needs responsive updates while the broader application architecture is moving toward managed backend services.

Approach

Use Supabase-backed realtime capabilities while maintaining GitHub as the code source of truth and keeping backend responsibilities clearly separated.

Challenge

Protecting private internal implementation

The application contains private employee workflows, API behavior, and internal service details.

Approach

Publish conceptual architecture and product behavior only; omit credentials, private endpoints, production data, and proprietary source code.
